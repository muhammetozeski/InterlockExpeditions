# Why this knowledge is kept

The product combines role-private views with shared machine state. An interface that looks cooperative can still be wrong if stale actions cross stages, a removed player can write, a timer keeps moving while paused or a retry completes a stage twice. Verified relationships between these layers are worth preserving because rebuilding them from generic framework tutorials would not transfer this product's rules.

Documentation is shared evidence for humans and future contributors. It records reusable behavior and its limits rather than a history of commands. Publication, payment and customer demand are separate claims and require their own observed evidence.
