# Knowledge maintenance

This library preserves Interlock Expeditions behavior that a later contributor would otherwise have to rediscover. The [purpose](Purpose.md) explains its role; the [index](INDEX.md) directs readers to existing topics. Read only the branches relevant to the actual task.

Describe implemented contracts, diagnosed failures, verification conditions and the relationship between the room engine, persistence and player projection. Cite the relevant source definition or an actual execution result. Distinguish source inspection, official documentation and exercised behavior. Do not present an untested proposal as a working method.

Keep one source of truth per topic. When behavior changes, update that article and nearby index links. General tutorials, speculative business plans, raw outputs and temporary task lists belong outside this knowledge library. Use dated Walkthrough records for current progress and lessons affecting continuation.

Every local document link must reach an existing file. Prefer a small example that transfers the implementation rule over a pasted log. Never include credentials, private room data or real player records in documentation. English is the project language.
