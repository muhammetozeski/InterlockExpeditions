# Club capacity and provider boundary

Free hosts can keep two active rooms with six guest devices each. Club supports twelve active rooms and twelve devices per newly created room. Existing room capacity is a snapshot; buying Club does not rewrite a running room. All six episodes are available to free hosts and guests never buy admission to another host's room.

`server/billing.mjs` implements actual Stripe Checkout, the subscription management portal and a signed webhook. The current deployment has no Stripe configuration; checkout remains unavailable. No live charge, subscription or real-provider webhook has been exercised. Thirty checks execute production routing, signature verification and SQL against in-memory provider response fixtures, which is a different evidence boundary.

Owner configuration requires `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` and `STRIPE_CLUB_PRICE`. All must describe live mode. The price must be active, recurring, nonzero and monthly or yearly. `scripts/Configure-Payments.ps1` validates the price against Stripe and writes only this product's variables to Cloudflare. It has not been used with real Stripe credentials. It patches only named variables, following the official [Wrangler Pages secret implementation](https://github.com/cloudflare/workers-sdk/blob/main/packages/wrangler/src/pages/secret/index.ts), and checks that PRIVATE_SALT plus all payment bindings still have secret types. It never replays redacted secret values from a GET. No live secret-preservation experiment was performed just for this script. Owner configuration must also create a webhook for `/api/billing/webhook` and enable the Stripe customer portal. Publish after changing production variables.

The raw webhook body is checked against the `Stripe-Signature` timestamp and HMAC, with a five-minute tolerance. Test events cannot grant capacity. The notification's account metadata is never an ownership source: the service must already have recorded the provider Checkout session for that host. After a completed paid session, it retrieves the canonical subscription and expanded latest invoice/payment/charge. The integration intentionally pins `Stripe-Version: 2024-06-20`, whose representation exposes the checked fields. An owner updating the API version must update these checks and fixtures together.

An allowance needs a live active single-item configured-price subscription, quantity one, a future paid period, a paid nonzero latest invoice, a succeeded payment and a live paid charge without refund or dispute. Trial, unpaid, paused, canceled, wrong-price, test and expired states do not grant capacity. A current-period partial refund also removes the allowance. Period-end cancellation preserves an already paid period until its end. Canonical current state, rather than event arrival order, controls revocation.

Each subscription reconciliation reserves an increasing generation before reading Stripe. Its final write must still own that generation, so an older delayed read cannot overwrite a later cancellation. Accepted event IDs are bound to their body fingerprints. Concurrent browser tabs reserve one open provider Checkout nonce before any provider creation call. Returning to `/membership` is only navigation and cannot grant anything.

Account erasure is blocked during an open checkout or an active paid allowance. The owner can use Manage subscription to cancel and wait for the paid period to end. The service stores provider reference IDs, status and paid-period expiry, not card details. There is no client premium toggle, forged checkout success path or subscription recovery promise for guests.

Primary references: [Checkout Session creation](https://docs.stripe.com/api/checkout/sessions/create), [webhook signature/body handling](https://docs.stripe.com/events/manage-webhook-endpoints), [subscription objects](https://docs.stripe.com/api/subscriptions/object), [customer portal sessions](https://docs.stripe.com/api/customer_portal/sessions/create). These document provider behavior; the exercised implementation results above come from this project's fixtures. Advertising is not included in this release; no advertising script or consent placeholder is loaded.
