# Minimal-reading handover

This directory preserves enough current context and learned experience for a contributor to continue without reconstructing the conversation. Read this method once per new context. Then inspect a bounded list of filenames, choose the newest overall context and relevant later lessons, and stop when the task is understood. An accumulation record, when present, states what it covers; do not assume it covers newer records.

Every meaningful result gets a new file named `yyyy.MM.dd HH.mm.ss - Meaningful outcome.md`, using the actual local time of writing. Do not overwrite an existing record. Keep the current objective, the observation that changed the approach, the verified result and any unresolved boundary in a few clear paragraphs. Never invent prior events or user approval.

Docs is the reusable knowledge library; this directory is concise continuation context. Link to detailed knowledge rather than copying it. Do not turn Git history, file inventories, raw logs or a task diary into handover prose. Add an accumulation only when it would reduce the number of older records needed. Correct a disproved lesson in a new searchable record and preserve the historical source.

Use known evidence without repeating tests merely to create a record. A source change or new condition can justify a targeted recheck. Verify only the new record's support and actual links. This economy governs handover work, not the quality or completeness of the product itself.
